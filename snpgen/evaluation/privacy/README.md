# Privacy Evaluation Module

Privacy metrics for evaluating whether synthetic SNP data generated by the VAE + Latent Diffusion Model preserves patient privacy from the training set.

## Overview

This module measures several forms of similarity and attack performance that can reveal potential memorization or disclosure in synthetic genotypes. These diagnostics cover only the evaluated attacks and distance geometry; near-chance scores and zero exact matches do not establish a privacy guarantee.

It evaluates privacy by comparing synthetic (or reconstructed) samples against real training data using distance-based metrics. A holdout test set serves as a calibration baseline — real unseen samples from the same population.

## Metrics

| Metric | What it measures | Ideal value | Interpretation |
|--------|-----------------|-------------|----------------|
| **IMR** (Identical Match Rate) | Exact copies of training samples in synthetic data | 0% | >0% means direct memorization |
| **DCR** (Distance to Closest Record) | Min distance from each synthetic sample to nearest training sample | ≈ holdout DCR | If syn DCR << holdout DCR → memorization |
| **NNAA** (Nearest Neighbor Adversarial Accuracy) | Whether synthetic samples are preferentially close to training data | ~0.5 | <<0.5 → synthetic too close to training |
| **MI** (Membership Inference) | Can we distinguish train vs holdout by distance to synthetic? | AUC ~0.5 | AUC above 0.5 indicates separation by this evaluated distance attack |
| **NNDR** (Nearest Neighbor Distance Ratio) | Ratio of 1st/2nd nearest neighbor distance (copying detection) | ~1.0 | <<1.0 → synthetic copies specific real samples |
| **MAF** (Allele Frequency Drift) | Per-SNP allele frequency correlation between real and synthetic | r > 0.99 | Fidelity check; complements privacy metrics |
| **Case-control delta** | Per-SNP case-minus-control allele-frequency shift in real and synthetic cohorts | High correlation; slope near 1 | Conditional-fidelity check; does not measure privacy |
| **Yelmen privacy loss** | `AA_TS(test) - AA_TS(train)` on equal, class-matched cohorts | ~0 | Higher values indicate greater train/test separation |
| **Nearest-neighbour chains** | T/S source patterns along loop-free nearest-neighbour chains | Context dependent | Exposes geometry hidden by averaged NNAA |

## Split protocol and in-place upgrades

Synthetic-cohort privacy uses the true gradient-fitting split as `real_train`,
the validation split separately, and the untouched test split as the holdout.
MAF and case-control-delta remain fidelity metrics referenced to `train_val`.
Record-derived VAE reconstructions also retain `train_val` as their source
reference because those files reconstruct that exact cohort.

Every synthetic result directory contains `privacy_manifest.json`, including
size and nanosecond-mtime identities for the real and synthetic inputs. When a
legacy result without the corrected manifest is evaluated, split-dependent
IMR/NNDR/NNAA/DCR/MI values are removed and recomputed in place. Existing MAF
and case-control-delta results are retained. The stale values are not archived
under another name. Matching manifests allow interrupted jobs to resume without
recomputing completed metrics.

The Yelmen-compatible calculation follows the AA_TS privacy-loss definition of
Yelmen et al. (2023), `AA_TS(test) - AA_TS(train)`, with equal-sized,
class-matched cohorts. It defaults to Manhattan distance, as their published
`computeAATS.py` implementation uses city-block distance. The result is named
`yelmen_privacy_loss`, distinct from SNPgen's historical NNAA `privacy_score`.
Nearest-neighbour chains are a separate geometry diagnostic based on their
chain analysis and use Hamming distance here. These are protocol adaptations;
they do not make the evaluated SNP panels or threat model identical to the
published study.
Both additions run overall by default; `--yelmen-per-class` and
`--chains-per-class` enable the substantially more expensive stratified forms.

## Module Structure

```
privacy/
├── __init__.py          # Public API exports
├── distances.py         # GPU-accelerated (+ CPU fallback) batched k-NN
├── metrics.py           # PrivacyEvaluator and standard metrics
├── yelmen.py            # AA_TS privacy loss and chain analysis
├── visualization.py     # Plotting functions for each metric
├── utils.py             # Data loading, persistence, helpers
└── README.md            # This file
```

### Key files

- **`distances.py`**: Batched k-NN supporting Hamming distance (via one-hot matmul trick on GPU) and Manhattan distance (via cuML or torch.cdist). Auto-detects GPU availability; falls back to sklearn on CPU.
- **`metrics.py`**: Implements the standard SNPgen metrics and the `PrivacyEvaluator` orchestration, including case-control allele-frequency calibration, with **incremental saving** (results saved after each metric to survive crashes).
- **`visualization.py`**: KDE plots (DCR), bar charts (NNAA), ROC curves (MI), histograms (NNDR), scatter plots (MAF), and summary tables.
- **`utils.py`**: `PrivacyDataBundle` dataclass, checkpoint-based and manual data loading, pickle/JSON persistence.

## Quick Usage

```python
from snpgen.evaluation.privacy import (
    PrivacyEvaluator,
    load_privacy_data_from_checkpoint,
    load_privacy_data_manual,
    plot_privacy_summary_table,
)

# Load data from a checkpoint with config.yaml
bundle = load_privacy_data_from_checkpoint(
    ddpm_checkpoint_dir="/path/to/ddpm_checkpoint/",
    model_name="T2D",
)

# Or manually for models without config.yaml
bundle = load_privacy_data_manual(
    dataset_path="/path/to/real_data.hdf5",
    ddpm_checkpoint_dir="/path/to/ddpm_checkpoint/",
    vae_checkpoint_dir="/path/to/vae_checkpoint/",
    model_name="CAD",
    seed=42,
)

# Run evaluation
evaluator = PrivacyEvaluator(distance='hamming', per_class=True)
results = evaluator.evaluate(
    bundle,
    output_dir="/path/to/ddpm_checkpoint/privacy_results",
    eval_target='synthetic',  # or 'reconstructed'
)
```

## Distance Metrics

**Hamming** (default): Counts mismatching SNP positions. Natural for discrete {0,1,2} data.
- GPU implementation uses the one-hot matmul trick for fast batched computation.

**Manhattan (L1)**: Sum of absolute allele count differences. Dosage-aware (0→2 counts as 2, 0→1 counts as 1).
- Uses cuML NearestNeighbors if available, otherwise batched torch.cdist.

Both have CPU fallbacks via sklearn NearestNeighbors.

## Output Format

Results are saved in three files:
- **`privacy_results.pkl`**: Full pickle with all result dataclasses (including distributions for plotting).
- **`privacy_summary.json`**: Human-readable JSON with scalar metrics only.
- **`privacy_manifest.json`**: Split definitions, distances, sampling limits, input paths and completed keys.

Save locations:
- Synthetic privacy → `{ddpm_checkpoint_dir}/privacy_results/`
- Reconstruction privacy → `{vae_checkpoint_dir}/privacy_results/`
